# Sonya's Walking Gallery

Walking Gallery работает как статический раздел `sonyae.art`, опубликованный через GitHub Pages.

## Источник истины

- конфигурация работ: `content/walking-gallery.json`
- одобренные остановки: `content/walking-gallery-stops.json`
- исходные изображения работ: обычные assets сайта
- пользовательские фото после одобрения: `assets/wg/stops/<SWG-ID>/...jpg`

На публичной карте отображается только то, что уже закоммичено в GitHub.

## Модерация

Пользовательская заявка идёт через маленький Cloudflare Worker в приватный Telegram владельца. Telegram — интерфейс очереди: `Одобрить` / `Отклонить`. Отдельной админ-страницы и отдельного постоянного хранилища нет.

При одобрении Worker делает commit в `main`: добавляет фото и обновляет JSON маршрутов. GitHub Pages затем публикует новую версию сайта.

Код шлюза и инструкция: `worker/walking-gallery/`.

## QR и маршруты GitHub Pages

GitHub Pages не поддерживает серверные rewrite-правила, поэтому короткий QR-маршрут и страница работы существуют как реальные статические каталоги:

- `/1/` → `/wg/001/`
- `/wg/001/` → страница SWG-001

Для каждой новой работы добавляется такой же короткий каталог и каталог `wg/<slug>/`.

## Перед запуском SWG-001

1. Добавить реальное изображение и название SWG-001 в `content/walking-gallery.json`.
2. Развернуть Worker и задать его secrets.
3. Записать `/submit` URL Worker в `project.submitEndpoint`.
4. Проверить с телефона: QR → фото → Яндекс → Telegram → Одобрить → GitHub commit → новая точка на карте.
5. Только после end-to-end теста объединять draft PR с `main`.
